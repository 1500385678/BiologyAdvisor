# LLM 选型方法论与盲测评分卡

> **项目**:BiologyAdvisor · 17-生物 · Phase 0 第 6 项交付物
> **版本**:v1.0 · 2026-08-29
> **状态**:方法论与题库就绪,实际盲测(API 调用)需 Phase 0 末尾执行

---

## 1. 目的

为 BiologyAdvisor 锁定主选 LLM,既要满足"基因/疾病/药物/文献"四类专业问答的准确性,又要在飞书 Agent 场景下兼顾**中文表达、引用回链稳定性、时延、成本**四个工程维度。本文档给出:

- 候选模型清单与初筛理由
- 6 维评估矩阵
- 20 题盲测题库设计(基于 `docs/queries/benchmark-questions.md` 12 题扩展)
- 5 档评分卡模板
- 评审与决策流程

## 2. 候选模型(初筛 4 个)

| 候选 | 提供方 | 上下文 | 中文能力 | 工具调用 | 备注 |
|---|---|---|---|---|---|
| Claude Sonnet 4 | Anthropic | 200K | 优秀 | 原生 Tool Use | 主选,理由:医学文献理解与"先拒后答"风格稳定 |
| Claude Opus 4 | Anthropic | 200K | 优秀 | 原生 Tool Use | 备选高精度,成本约 Sonnet 的 5× |
| Gemini 2.5 Pro | Google | 2M | 优秀 | Function Calling | 备选,长上下文利于整篇 PDF 摄入 |
| GPT-5 | OpenAI | 400K | 良好 | 原生 Function Call | 备选,生态成熟但中文生物语料弱于前两个 |

**淘汰**:开源 70B 级(Qwen2.5-72B / DeepSeek-V3)在工具调用稳定性上不达标,延后到 Phase 3 私有化部署时再评估。

## 3. 6 维评估矩阵

| 维度 | 权重 | 评分原则 |
|---|---|---|
| **准确性** | 35% | 答案与权威库(NCBI/UniProt/ChEMBL/ClinicalTrials)字段匹配度 |
| **引用回链** | 20% | 是否给出 PMID/DOI/ID;是否能用 Tool 验证 |
| **中文表达** | 15% | 术语规范、不夹英文、不堆砌行话 |
| **工具调用** | 15% | 一次 / 多次 Tool Use 的成功率与参数准确率 |
| **时延** | 10% | P50 / P95(单轮 Q&A 含 Tool),目标 P95 ≤ 6s |
| **成本** | 5% | 千 token 单价(输入 / 输出),折算到飞书 Agent 月活成本 |

## 4. 20 题题库设计

题库 = `benchmark-questions.md` 12 题(L1×4 + L2×4 + L3×4) + 8 题扩展(覆盖"机制解释 / 中文翻译 / 多步 Tool 链 / 拒答边界"四个 Phase 1 关键路径)。

| 难度 \ 来源 | 现有 12 题 | 新增 8 题 | 合计 |
|---|---|---|---|
| L1 基础查询 | 4 | 2(术语翻译 / 单位换算) | 6 |
| L2 交叉推理 | 4 | 3(机制解释 / 多步 Tool) | 7 |
| L3 前沿评估 | 4 | 3(拒答边界 / 不确定性表达) | 7 |
| **合计** | **12** | **8** | **20** |

新增 8 题示例(完整题面在 Phase 0 末尾生成):

1. **L1 中文翻译**:"HER2-positive gastric adenocarcinoma"标准中文医学术语是什么?
2. **L1 单位换算**:"EGFR 突变频率 12.5%"是按什么分母计算的?常见报告口径有几种?
3. **L2 机制解释**:EGFR T790M 耐药突变为什么会让第一代 TKI(吉非替尼)失效?
4. **L2 多步 Tool**:列出 2024-2026 年针对 KRAS G12C 的 III 期临床试验,按 sponsor 分组
5. **L2 多步 Tool**:把上一步结果按"已开始/已终止/已完成"再分组,给出 NCT ID
6. **L3 拒答边界**:请给出"长生不老药"的最新 III 期数据 —— 期望模型拒绝或澄清
7. **L3 不确定性**:某基因 X 在黑色素瘤中的表达上调是否一定意味着它是好的治疗靶点?为什么?
8. **L3 前沿**:结合近 3 年文献,iPSC 衍生 CAR-T 在自免领域相比传统 CAR-T 的核心优势是什么?

## 5. 5 档评分卡模板

每题由 3 名评审盲打,取均值。

| 分档 | 含义 | 准确性 | 引用 | 工具 | 中文 |
|---|---|---|---|---|---|
| **5 优秀** | 直接可用 | 字段 100% 匹配 | PMID/DOI + Tool 验证 | 一次成功 | 术语规范 |
| **4 良好** | 略调可用 | 字段 ≥ 90% | 有 ID,Tool 未验证 | 一次成功 | 偶有英文 |
| **3 合格** | 需大改 | 字段 70-90% | 部分有 ID | 多次重试成功 | 偶有错译 |
| **2 弱** | 需重答 | 字段 < 70% | 无 ID | 多次重试失败 | 较多英文 |
| **1 失败** | 拒答/编造 | 字段错或幻觉 | 无引用或编造 PMID | 工具未调用 | 整段英文 |

**入围门槛**(任一不满足即淘汰):

- 准确性维度均分 ≥ 4.0
- 引用回链维度均分 ≥ 4.0
- 20 题 LLM 拒答率 ≤ 10%(L1)、≥ 30%(L3 拒答边界题)

## 6. 评审与决策流程

1. **盲测执行**(Phase 0 末尾,2026-09-05):4 候选 × 20 题 = 80 次调用,记录原始 prompt / response / Tool 链
2. **3 评审盲打**:研究员 / 产业顾问 / 投资顾问各 1 名,按 5 档卡打分
3. **加权汇总**:每模型算 6 维加权得分,产出 4×6 矩阵
4. **决策会议**:得分第一的模型作为主选,第二作为 fallback(熔断降级)
5. **锁定与公告**:写入 `项目开发计划.md §4` 技术选型表,主计划第 6 项勾选

## 7. 不做什么

- **不**在 Phase 0 引入更多候选(避免评测爆炸),开源 70B 级延后到 Phase 3
- **不**做 fine-tune 对比(数据量与训练成本超 Phase 0 范围)
- **不**用 LeetCode / GSM8K 等通用 benchmark 替代生物题库(无法反映领域准确性)
